# registry.local résolu via curl --resolve (pas de sudo pour /etc/hosts) ; vérification TLS stricte avec --cacert certs/ca.crt
$ curl https://registry.local:5000/v2/
{"errors":[{"code":"UNAUTHORIZED","message":"authentication required","detail":null}]}
 -> HTTP 401
$ curl https://registry.local:5000/v2/ (sans --cacert : certificat non reconnu)
000 SSL certificate problem: unable to get local issuer certificate
$ curl -u dev:dev-pull-2024 https://registry.local:5000/v2/_catalog
{"repositories":["shopapi"]}

$ curl -u dev:mauvais https://registry.local:5000/v2/_catalog
HTTP 401
$ openssl s_client -connect 127.0.0.1:5000 -servername registry.local -CAfile certs/ca.crt | grep Verify
Verify return code: 0 (ok)

# Côté daemon : CA installée dans ~/.docker/certs.d/{registry.local,localhost}:5000/ca.crt (Docker Desktop) ; nom localhost:5000 faute d entrée /etc/hosts
$ docker login localhost:5000 -u ci
Login Succeeded
$ docker tag shopapi:1.4.2 localhost:5000/shopapi:1.4.2 && docker push localhost:5000/shopapi:1.4.2
1.4.2: digest: sha256:3496d0e358dba9e3ebe365be77d853abc5762072b75b94e575de62bb1431d041 size: 856

# Remarque : 127.0.0.0/8 fait partie des "insecure registries" par défaut du daemon
# (docker info -f '{{json .RegistryConfig.InsecureRegistryCIDRs}}' -> ["::1/128","127.0.0.0/8"]) :
# avec le nom localhost:5000 le daemon accepterait un certificat non reconnu ; seul registry.local:5000
# (entrée /etc/hosts) permet de tester la validation stricte côté daemon.
