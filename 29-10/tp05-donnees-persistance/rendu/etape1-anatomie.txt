## Couche inscriptible du conteneur vs volume
$ docker compose exec db touch /tmp/x && docker compose exec db sh -c "echo test > /var/lib/postgresql/data/marqueur"
$ docker diff $(docker compose ps -q db)
C /docker-entrypoint-initdb.d
A /docker-entrypoint-initdb.d/001-init.sql
C /tmp
A /tmp/x
C /run
C /run/postgresql
A /run/postgresql/.s.PGSQL.5432
A /run/postgresql/.s.PGSQL.5432.lock
A /run/secrets
A /run/secrets/db_password
=> /tmp/x apparaît (couche inscriptible du conteneur, overlayfs "upperdir") ; "marqueur" n apparaît PAS : il est écrit dans le volume, hors du système de fichiers en couches.

## Cycle de vie de pgdata — sur une COPIE de la stack : docker compose -p shopcopy -f compose.yml (service db seul)
$ docker compose -p shopcopy -f compose.yml up -d --wait db
 Container shopcopy-db-1  Healthy
$ docker compose -p shopcopy logs db | grep docker-entrypoint-initdb.d   (1er démarrage : volume vide -> init.sql exécuté)
/usr/local/bin/docker-entrypoint.sh: running /docker-entrypoint-initdb.d/001-init.sql
$ psql -c "INSERT INTO products(name,price) VALUES (temoin,1)"
INSERT 0 1
volumes : shopcopy_pgdata 

### docker compose down
2 objets supprimés (conteneurs, réseaux)

après up : témoin = 1  -> données conservées

### docker compose rm -sf db
 Container shopcopy-db-1  Removed
volumes : shopcopy_pgdata 
après up : témoin = 1  -> données conservées (rm ne touche pas aux volumes nommés)

## Volume anonyme
$ docker run -d --name pg-anon -e POSTGRES_PASSWORD=x postgres:16.4-alpine
$ docker inspect pg-anon --format "{{json .Mounts}}"
{"Type":"volume","Name":"68c719b79c07a8054bbf0af2a353316e4af1bcf59efa9464f1a47449de4dcc5e","Destination":"/var/lib/postgresql/data"}
=> volume déclaré par "VOLUME /var/lib/postgresql/data" dans le Dockerfile de l image : nom aléatoire, aucun label compose
